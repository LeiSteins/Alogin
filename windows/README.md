# Alogin Windows

Rust + Slint 的 Windows 原生客户端，目标系统为 Windows 10/11 x64。

## 下载与使用

当前版本为 **v0.0.2**，Git 标签为 `windows-v0.0.2`。前往
[Windows v0.0.2 Release](https://github.com/LeiSteins/alogin/releases/tag/windows-v0.0.2)
下载 `alogin-windows-v0.0.2-x64.zip`，也可使用[服务器下载](https://aloginupdate.steins.top/windows/alogin-windows-v0.0.2-x64.zip)。
核对同名 `.sha256` 文件后，将 ZIP 解压到固定目录，运行 `alogin-windows.exe`。
程序无需管理员权限，支持在设置中启用开机自启；移动目录后需要在新位置重新启用。

关闭主窗口后程序继续在托盘运行。更新时先在托盘菜单选择“退出”，再覆盖程序文件。
账号与设置保存在 `%LOCALAPPDATA%\Alogin\`，更新时保留该目录。
本版 EXE 未进行 Windows 代码签名，尚不提供客户端自动更新。发布包包含 GPL-3.0 许可、
第三方依赖声明及许可文本，`SOURCE.txt` 提供对应版本源码和构建入口。

## 当前功能

- 单实例和系统托盘，关闭主窗口后销毁窗口及控件，保留后台监听；再次运行可打开已有实例。
- 托盘右键菜单顶部显示当前 Wi-Fi 名称；有线连接、未连接及 Wi-Fi 名称不可读分别提示。菜单采用紧凑间距、较窄宽度和无外框描边的 8 逻辑像素圆角，保留内部分组线，过长名称省略显示；按网络信息、常用操作、快捷开关和退出分组，支持键盘操作、DPI 缩放及高对比度。已认证时“登录”变为不可重复提交的“已登录”；登录、刷新及切换开关后菜单保持打开，直接更新处理状态和结果，选择“打开 Alogin”、退出程序、按 Esc 或点击菜单外部时关闭。“登录维持”和“开机自启”与设置页共用后台保存逻辑，主窗口关闭后仍可切换；保存失败保留原状态，错误提示在关闭菜单后展示。
- 程序文件、窗口、任务栏及托盘使用 Windows 独立图标，源图位于 `resources/icon.png`。
- 左侧图标导航切换“主页”“账号管理”“目标网络”“登录维持”，顶部菜单按钮可展开或收起侧栏，宽度与导航文字透明度使用 180ms 平滑过渡，动画中可反向切换；收起后保留图标、键盘操作和无障碍名称。页面内容显示在右侧：主页显示网络状态，仅认证后显示在线账号概览；账号管理直接以可滚动列表展示本地账号，点击列表项切换当前账号，选中项高亮显示，列表下方可修改或删除账号；目标网络配置 Wi-Fi；侧栏底部新增“设置”和“关于”页面，设置直接展示与 Android 软件设置一致的外观选择和自动登录开关，关于展示应用信息与项目链接。切换页面及收起导航保留未保存输入，窗口不显示底部状态栏及使用提示，手动操作失败时弹窗提示。
- 主页右下角合并登录和刷新按钮：连接目标 Wi-Fi 且门户确认未认证时显示“登录”，有线网络只需确认未认证；已认证、状态未知、非目标 Wi-Fi、Wi-Fi 名称不可读或断网时显示“刷新状态”。处理期间禁用并显示“正在处理…”。执行前重新核对网络，登录使用账号管理中选定的账号，手动操作不受自动登录开关限制。
- 窗口采用与 [WSL Dashboard](https://github.com/owu/wsl-dashboard) 相近的布局与配色：侧栏和原生标题栏共用外框底色，右侧内容区独立配色并保留左上圆角；深色模式外框为 `#2D2D30`、内容区为 `#1E1E1E`。主页使用 12 逻辑像素圆角的细边框卡片，网络信息卡片和在线账号卡片共用宽度，最小 250、最大 600 逻辑像素。两张卡片并排时，每张可分配宽度不足 300 逻辑像素即换行（含 20 逻辑像素间距的卡片内容区宽度小于 620 时）；网络卡片在第一行，账号卡片在第二行，行间距同为 20 逻辑像素。单列时卡片按内容区宽度伸缩并限制在 250–600 逻辑像素，内容过高时可滚动查看第二行。两张卡片统一使用强调色标题、14 逻辑像素灰色标签、18 逻辑像素加粗信息和四周 16 逻辑像素内边距，各自按内容和换行自适应高度，不在底部额外填充空白；网络卡片仅显示网络名称和 IPv4。默认客户区为 860 × 560 逻辑像素，最小支持 660 × 386，可随窗口扩展；内容过高时卡片区域可滚动，操作按钮保持在右下角。高对比度模式使用系统配色和清晰轮廓。
- 导航采用柔和选中底色、左侧强调色指示条和 SVG 线条图标，顶部按钮在侧栏展开时显示 `panel-left-close`，收起时显示 `panel-left-open`，其下依次为 `house`、`folder-user`、`wifi`、`globe-check`，底部为 `settings`、`info`。源文件位于 `resources/navigation/`，随构建嵌入 EXE，无需旁加载。图标统一为 16 逻辑像素，通过主题动态着色，适配浅色、深色、高对比度及选中、悬停、按下状态。导航与操作按钮均使用 Slint 圆角组件；鼠标点击不显示焦点边框，键盘操作时显示焦点提示，禁用时弱化文字。
- 界面跟随 Windows 应用浅色/暗色设置，响应运行中的系统主题切换；窗口背景、标题栏、文本、输入框、按钮、复选框、账号列表与托盘菜单同步适配。设置页支持跟随系统（默认）、浅色和深色，选择持久化保存，高对比度始终优先使用系统配色。标题栏、侧栏与托盘菜单共用外观选择。
- 多账号添加、修改、切换与删除。“添加账号”和“修改账号”在窗口内部打开居中的输入弹窗，背景压暗并阻止操作；支持取消和 Esc 关闭，重新打开保留未提交的添加草稿。保存成功后关闭，失败时保留弹窗供重试。密码输入留空时保留已有密码；切换保存账号不会改变当前校园网认证身份。
- 设置页提供“开机自启”开关，默认关闭。启用后在当前 Windows 用户登录时自动启动到托盘，不弹出主窗口；与“自动登录与掉线重登”独立控制。启动项使用当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中 `Alogin` 值，保存带引号的当前 EXE 绝对路径和 `--background`，无需管理员权限。状态从系统启动项读取，不重复保存在 JSON 中；修改由后台线程执行，失败保留原状态并提示错误。移动程序后需在新位置重新启用；Windows 任务管理器或系统策略禁用启动项时，需在系统中恢复。
- 使用当前 Windows 用户范围的 DPAPI 加密密码，配置位于 `%LOCALAPPDATA%\Alogin\settings.json`。
- 显示到校园网门户的路由接口 IPv4、可读取的 Wi-Fi 名称和手动刷新的认证状态。
- 系统网络通知先由后台核对完整物理网络快照；接口、连接类型、SSID 和 IPv4 均未变化时，不重新读取认证状态、账号概览或设备列表，不显示忙碌状态，也不重置登录维持的检测计划。首次启动、手动刷新、实际切网及请求期间收到通知导致旧结果失效后的重新检查仍正常执行。设备下线沿用读取列表时的 Cookie，会在每次操作开始记录通知代次，并在身份复核、提交前后持续校验该代次及网络快照。
- 登录成功、启动或网络变化后的状态检查，以及点击“刷新状态”时，读取当前在线账号、已用流量、剩余流量和账户余额。在线账号由门户确认，与下次登录使用的本地保存账号独立；自助服务读取失败时保留已认证状态和已确认的账号，未返回的数值显示“—”。
- 在线账号卡片依次显示强调色“已登录”状态、用户名与剩余金额双列及加粗数值、流量摘要和进度条。进度条上方左侧显示已用百分比，右侧显示“已用 / 总量”，例如 `6G / 30G`；总量为已用与剩余之和，未知总量显示“—”，不再在进度条底部显示流量。流量摘要与进度条行之间保留 4 逻辑像素间距，10 逻辑像素高的进度条在 23 逻辑像素高的行内垂直居中，与网络卡片的 IPv4 数值行对齐；正常单行且无错误时两张卡片等高，换行和错误状态仍按内容自适应。字号固定使用紧凑规格：标签 14 逻辑像素、账号与金额数值 18 逻辑像素、百分比与流量摘要 14 逻辑像素，与 IPv4 标签一致，窗口放大时不再增大。金额使用“元”为单位；未返回金额时隐藏金额列。进度按“已用 /（已用 + 剩余）”填充，百分比与 Android 一样取整数部分。只有身份已确认且两项流量均为有效非负数、总量大于零时显示比例；概览存在但比例不可用时显示“—”与中性空轨道，仍保留可用流量数值。读取概览失败时保留已确认用户名、显示错误与“重试获取”按钮，重试调用现有状态刷新。进度条沿用系统主题与高对比度配色，不使用持续动画或轮询。
- 主页第三张“在线设备”卡片参照 Android 显示 MAC、IP 和“本机”标记，本机优先排列，每行可点击红色“下线设备”。双列时设备卡片横跨网络与账号卡片，单列时位于账号卡片下方并保持同宽；列表随主页滚动，右下角操作按钮固定。空列表显示“当前没有在线设备”，读取失败显示错误与重试入口，保留已确认账号及可用概览。下线期间禁用重复操作，成功或结果不明确时刷新状态；下线本机后重新检查认证状态。
- 自动探测并使用 Android 版现有 WLGN / Eportal 认证流程；兼容 JSONP、UTF-8 和 GBK 响应，以及动态门户的在线状态查询。
- 目标 Wi-Fi 默认包含 `bjut_wifi`，连接名称以 `bjut-sushe-` 开头的宿舍 Wi-Fi 时自动将完整名称保存到目标列表，与 Android 一致；已保存的自定义列表保持原样。自动登录默认关闭。启用后在启动、网络变化或恢复唤醒后等待网络稳定，再持续检测；只有已保存的目标 Wi-Fi 且门户明确确认离线才提交认证，使用当前选中的保存账号。有线连接、非目标 Wi-Fi、SSID 不可读取或没有有效 IPv4 时等待网络变化，不进行后台认证。
- “目标网络”下一行新增“登录维持”，使用 `globe-check.svg`。页面显示运行状态和最近检测结果，可设置检测间隔（15、30、60、120 秒，默认 30 秒）、首次失败重试间隔（15、30、60 秒，默认 15 秒）和失败退避上限（2、5、10 分钟，默认 5 分钟）；与设置页共用“自动登录与掉线重登”开关。所有设置即时交由后台原子保存，写盘失败恢复原值，旧配置自动使用默认参数。
- 保活检测与认证在现有后台工作线程串行执行，关闭主窗口后继续在托盘检测，托盘退出后停止。登录失败按倍增间隔退避，期间继续检测；状态未知按 10、30、60 秒退避重查，不提交凭据，也不将检测失败当作掉线。密码错误或凭据无法解密时暂停自动重登，可修正凭据或点击“恢复检测与重登”；重新启用自动登录也会重置暂停。登录响应成功后约 3 秒复查认证状态，周期检查不反复获取账号概览或重建在线设备 Cookie 会话，概览读取失败不触发重新认证。
- 登录维持默认开启“主动下线本机后暂停自动重登”，成功或结果不明确时保留暂停，避免主动下线后立即被自动登录；可以手动登录、恢复检测、重新启用自动登录或在实际网络快照变化后恢复。下线其他设备不暂停。后台检测不会反复弹窗、清空草稿或将正在保存的账号及设置误报为成功。网络通知代次和完整物理网络快照共同校验，切网后的旧响应被丢弃。
- 目标网络页以可滚动列表展示目标 Wi-Fi，与账号列表共用行样式，点击后高亮选中，右下角可删除选中项。顶部“添加自定义WiFi”打开与添加账号相同样式的居中弹窗，输入完整名称并点击“添加”或按回车添加；也可点击顶部“添加当前连接的 Wi-Fi”。添加、删除以及设置页的自动登录与外观变更均立即交给后台线程保存，不再提供“保存网络设置”按钮；保存成功后才更新列表，失败时保留原设置并提示错误。自定义添加弹窗背景压暗并阻止操作，支持取消和 Esc 关闭，再次打开保留输入草稿；保存期间禁用提交和取消，写盘成功后关闭，失败时保留弹窗和输入供重试。添加时去除首尾空白、避免重复并检查 32 字节限制，已保存的重复名称仅定位选中。未连接 Wi-Fi、名称不可读取或含换行时禁用添加当前 Wi-Fi 按钮。

关于页使用 Windows 独立图标，版本和许可取自 Cargo 包信息；项目主页、源码和许可说明只打开编译内置的三个 HTTPS 链接。“检查更新”入口禁用并标注暂未接入更新服务，不执行请求或下载。

无感知绑定管理、附近 Wi-Fi 扫描及自动更新尚未移植。Windows 与 Android 独立版本和发布。

## 构建和运行

安装 Rust 1.92 或更新的 stable 版本及 `x86_64-pc-windows-msvc` 工具链、Visual Studio 的“使用 C++ 的桌面开发”组件和 Windows SDK。Slint 固定为 1.18.1，使用 Winit 窗口后端与软件渲染；不需要 Qt、Skia、WebView2、Java 或 .NET。构建脚本编译 `ui/main.slint`，界面和图标随 EXE 分发，无需旁加载 Slint 文件。

`src/ui/repaint.rs` 回移植 Slint [#13568](https://github.com/slint-ui/slint/pull/13568) 的 Windows 重绘修复：绘制前将原生失效区域同步到 Slint，避免最小化期间局部刷新后恢复窗口时出现透明背景，也处理系统请求的重绘。该适配通过同版本固定的 `i-slint-core` 访问渲染器；升级到包含修复的 Slint 后应一并移除适配模块和这项直接依赖。

在仓库根目录执行：

```powershell
# 标准 Rust 安装与本仓库内 .tools 工具链都可以使用此入口
.\windows\scripts\cargo.ps1 test --locked
.\windows\scripts\cargo.ps1 fmt --check
.\windows\scripts\cargo.ps1 clippy --locked --all-targets '--' -D warnings
.\windows\scripts\cargo.ps1 build --locked --release

# 显示管理窗口
.\windows\target\release\alogin-windows.exe

# 仅启动托盘
.\windows\target\release\alogin-windows.exe --background
```

也可以在 `windows` 目录直接执行标准 `cargo` 命令。`Cargo.lock` 纳入版本控制，Release 使用 LTO、体积优化和符号剥离。当前开发环境的工具链安装在被 Git 忽略的 `.tools` 下，不修改系统 PATH；上述脚本自动识别它。

通过 PowerShell 包装脚本传递 Clippy 参数时将 `'--'` 加引号，防止 PowerShell 提前消耗参数分隔符；直接调用 `cargo` 时使用普通的 `--` 即可。

推荐使用 VS Code + rust-analyzer 或 RustRover，并打开 `windows/Cargo.toml` 对应的项目。使用仓库内工具链时，IDE 的 `CARGO_HOME` 和 `RUSTUP_HOME` 需分别指向仓库的 `.tools/cargo` 和 `.tools/rustup`；可先用标准 rustup 安装系统用户级工具链来简化 IDE 配置。

## 架构和资源占用

```text
src/
├── ui.rs             Slint 事件循环、状态绑定、隐藏 Win32 消息窗口与托盘
├── ui/theme.rs       系统配色到 Slint 的映射、标题栏与托盘菜单主题
├── ui/tests.rs       无窗口交互与渲染测试、独立原生窗口生命周期测试
├── strings.rs        Windows 客户端中文文案
├── app.rs            会话状态、命令、后台串行工作线程
├── domain.rs         配置模型、自动登录准入、协议解析与编码
├── maintenance.rs    后台检测截止时间、失败退避与暂停规则
├── network.rs        校园网认证与门户状态流程
├── account.rs        门户账号确认、SSO 会话、账号概览及在线设备读写
├── storage.rs        DPAPI、配置校验与原子持久化
└── platform/
    ├── http.rs       WinHTTP 请求、超时、响应上限与句柄释放
    ├── icon.rs       嵌入图标资源加载
    ├── startup.rs    当前用户开机自启注册表读写
    └── network.rs    路由、适配器、SSID 和系统网络事件
```

界面定义位于 `ui/main.slint`，设置与关于页面位于 `ui/preferences.slint`，登录维持页面位于 `ui/maintenance.slint`，账号卡片位于 `ui/account-card.slint`，在线设备卡片位于 `ui/device-card.slint`，通用控件位于 `ui/widgets.slint`，配色契约位于 `ui/theme.slint`；用户文案与账号展示字段的格式化仍集中在 `src/strings.rs`。Slint 负责布局、缩放、焦点和渲染，Win32 仅承担系统集成。首次打开和托盘恢复统一排入事件循环；由于 Slint 的 `show()` 可能先于原生窗口创建返回，图标、标题栏颜色和前台激活在首个 Winit 原生窗口事件到达后初始化，不通过定时器轮询。

UI 线程只处理消息，凭据初始化、加解密、磁盘读写及请求由一个后台线程串行执行。网络通过 IP 地址、接口、路由和 WLAN 通知驱动，事件用 250ms 短期定时器合并；启用登录维持且处于目标 Wi-Fi 时，工作线程通过带截止时间的命令等待执行周期检测，其他情况下阻塞等待命令，无持续渲染。可见窗口按需创建并在关闭时销毁，后台仍保留消息接收窗口、托盘和网络订阅。后台检测结果与手动命令完成结果分别处理，避免误关编辑弹窗或丢弃手动操作结果。Win32 消息通过 Slint 事件队列投递，界面更新与原生窗口回调分开执行；退出托盘时显式结束事件循环。WinHTTP/Windows 可能创建自己的内部线程。

主题检测仅在窗口创建及系统主题变化通知时执行，不轮询。Slint 控件提供键盘操作、焦点提示和无障碍语义，并使用系统高对比度颜色；GDI 画刷只用于托盘菜单，随菜单释放。标题栏保留系统拖动、缩放和窗口按钮，使用 DWM 公开接口同步侧栏底色和文字颜色，进入高对比度模式时清除自定义标题栏颜色；较旧 Windows 版本不支持自定义颜色时保留系统标题栏。

`resources/alogin.ico` 从 Windows 独立源图 `resources/icon.png` 转换，包含 16–256 像素的多种尺寸，与 Android 图标分开维护。图标由 `build.rs` 使用 `embed-resource` 和 Windows SDK 资源编译器嵌入，构建时无需 Python。更新源图后，安装 Pillow 并运行 `python windows/scripts/generate_icon.py` 重新生成 ICO；仅转换格式，不重新绘制图案。

不承诺固定内存值。应在同一台机器上使用 Release 分别检查：启动并稳定后的托盘空闲、打开窗口、认证过程中和关闭窗口后的工作集、专用内存及 CPU 时间增量；不要只看累计 CPU 时间或可执行文件大小。

## 安全与使用边界

- 账号使用系统 DPAPI 加密，不提供明文回退。跨 Windows 用户或设备复制配置不保证可解密。
- 新配置先写同目录临时文件并刷盘，再执行写穿原子替换，成功后才提交内存状态。损坏或未知版本的配置不会被自动覆盖。
- 请求固定使用已实现的校园网主机和端口；关闭自动重定向和自动 Windows 身份认证，不记录请求 URL、密码或响应正文。自助服务跳转只接受 `jfself.bjut.edu.cn` 的 HTTPS 443 端口和 `/Self/` 路径，限制跳转次数。
- 校园网证书链兼容例外只用于 `wlgn.bjut.edu.cn`、`lgn.bjut.edu.cn`、`jfself.bjut.edu.cn`，仍检查主机名和有效期。Eportal 沿用现有校园网 HTTP 协议。
- 每次账号概览读取创建独立 WinHTTP Cookie 会话；设备列表成功读取后仅在后台内存中保留，用于对应列表的下线操作，刷新、切网、会话失效或退出时释放，Cookie 不写磁盘；SSO 请求使用门户确认的账号，不读取本地密码。每次请求前后复核网络，切网后丢弃旧结果；自助服务返回其他账号时拒绝显示其流量和余额。
- 设备下线仅接受当前列表内的设备，并同时核对列表代次、门户确认身份及包含连接类型的网络快照；提交前重新确认门户账号和网络，使用列表读取时的 Cookie 会话。过期会话不会自动重建后重发，下线请求不跟随跳转；传输失败或未知响应触发状态刷新并提示核对结果。
- 校园网快照只接受已连接的物理 Wi-Fi／以太网，按到固定门户的最长路由前缀和总跃点数选择网卡及首选源 IPv4，用于网络识别、展示及切网校验，排除 TUN／Hyper-V 虚拟网卡。登录提交前后核对接口、IP、连接类型和可读取的 SSID；自动认证还会重新检查目标网络。HTTP 请求仍遵循 Windows 路由，TUN 代理规则需允许校园网门户直连，VPN 和多网卡环境需要实网验证。
- Eportal 登录先从固定门户的 `/drcom/chkstatus` 读取 IP，失败时读取首页，按 `v46ip`、`ss5`、`v4ip` 顺序选择有效 IPv4；两处均无有效 IP 时停止，不使用本机地址替代。该接口的 `result` 不用于判断在线状态；取 IP 前后及提交凭据前复核物理网络快照，不缓存门户 IP。WLGN 登录仍不显式提交 IPv4。
- Windows 位置权限可能影响 SSID 读取。无法读取 SSID 时不会自动登录，主页显示刷新按钮；有线网络根据门户确认的登录状态显示主页按钮，仍不参与自动登录。托盘菜单保留手动认证入口。

## 验证

JVM/Android 构建不参与 Windows 客户端编译。Windows 修改至少运行 `test`、`fmt --check`、`clippy --all-targets -- -D warnings` 和 `build --release`；工作流 `.github/workflows/windows-client.yml` 在 Windows 执行这些检查并保留 EXE 构建产物。正式发布使用独立的 `.github/workflows/windows-release.yml`。

## 正式发布

1. 修改 `Cargo.toml` 版本，同步 `Cargo.lock`，新增 `release-notes/<version>.md` 中文说明。EXE 资源和应用清单版本由 `build.rs` 从 Cargo 版本生成。
2. 在仓库根目录运行 `python -m unittest discover -s windows/scripts -p 'test_*.py'`，以及上述 Rust 检查、本机安装和必要的原生验证。
3. 提交源码后推送 `windows-v<version>` 标签。不得复用已发布标签；Android 的 `v*` 标签独立保留。
4. Windows Release 工作流校验版本和说明，在 Windows runner 构建 x64 Release，生成便携 ZIP、SHA-256 和 `latest.json`。ZIP 包含 EXE、README、版本说明、源码链接和许可证。工作流先创建 GitHub 草稿，附件完整后发布，显式设置 `latest=false`。
5. 沿用 `production` 环境的 SSH 部署配置，在 `DEPLOY_PATH/windows/` 上传包和校验文件，远端 SHA-256 验证后原子替换清单，并验证公开 HTTPS 下载。拒绝降级和同版本不同内容覆盖；完全相同的部署可重跑，失败时保留旧清单。

Windows 清单位于 `https://aloginupdate.steins.top/windows/latest.json`，包含版本、平台、架构、下载文件名、固定来源下载 URL、大小、SHA-256 和说明；Android 的根目录 `latest.json` 保持独立。发布渠道提供下载分发，应用内检查更新仍禁用。

Slint 测试覆盖页面草稿和侧栏收起时的输入保留、侧栏动画插值及中途反向切换、忙碌状态、主页按钮、密码提交后清空、选择账号失败回滚、流量进度、数据不可用时的占位、概览失败时保留身份与重试准入，以及 Wi-Fi 名称字节限制。五个页面分别按最小尺寸和默认尺寸渲染浅色、深色和高对比度预览，并生成收起侧栏、双卡换行阈值两侧、单列滚动查看第二张卡片、卡片最大宽度、宽窗口卡片、单张网络卡片及缺失数据与长账号换行错误状态的预览，以及在线设备正常、空列表、读取错误、长 IP 换行和滚动状态预览，位于 `target/ui-previews/`；预览仅包含合成测试数据，CI 会将其作为单独产物上传。

原生窗口生命周期测试需要交互式 Windows 桌面，默认忽略，需单独执行：

```powershell
.\windows\scripts\cargo.ps1 test --locked native_host_keeps_running_hidden_and_recreates_the_slint_window '--' --ignored
```

该测试使用独立隐藏窗口和模拟工作线程，覆盖事件循环启动前排队打开窗口、首次显示的图标与配色、无窗口时接收结果、Slint 回调投递、关闭窗口释放资源、重新打开和托盘退出。最小化期间连续更新局部控件，分别通过原生恢复和应用唤起路径恢复窗口，并在深色、浅色和高对比度配色下直接读取显示中的侧栏与内容背景像素；读取前不调用截图或强制重绘，以免掩盖漏画。支持自定义标题栏颜色的系统上使用 `PrintWindow` 截取原生窗口，核对首次显示、浅色和深色切换以及重新打开后的标题栏与侧栏实际像素；高对比度切换恢复系统标题栏颜色。标题栏颜色是只写 DWM 属性，不使用 `DwmGetWindowAttribute` 读取它作为通过依据。测试不读取本地账号。

单元测试覆盖物理网卡筛选、路由优先级、首选源地址校验、门户 IP 解析及失败回退、缺少门户 IP 或切网时阻止凭据提交、响应解析、编码、自动登录准入、DPAPI 往返、损坏配置保护、持久化失败时保留旧磁盘和内存状态，以及账号确认、SSO 跳转校验、概览解析与格式化、在线设备解析、下线响应与未知结果、列表代次及成员准入、会话过期和切网结果隔离。DPAPI 测试需要当前 Windows 用户的正常加密权限；受限沙箱可能拒绝调用。
